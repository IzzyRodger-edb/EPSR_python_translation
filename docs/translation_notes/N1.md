## Uninitialised variables and quirks (reproduced or set to 0)

- `dockato`: `ndihedralangs` is reallocated but only set for DIH groups; new elements are 0
  (reallocation_routines gives zeros). The Rust port notes that the gfortran reference
  reads garbage there for a docking molecule with rotational groups; no test case has one.
- `dockato`: `imv` (used for `moltemplate(mtype(imv))` at the end) is undefined in the
  Fortran if no docking site is ever examined; 0 here (writes `moltemplate[0]`, unused).
- `bond_molecule`: `ig` is undefined in the Fortran if the docking molecule has no
  rotational groups and `nato(imv) <= 2`, and is then used for the DIH group; 0 here.
  Also, the shift of rotational groups copies `mref(ig)=mref(ig1)` (the atom->molecule
  map), not `mrot`, as in the Fortran.
- `bond_molecule`: with `atomdrr = 0` and `dminrr == dmaxrr` (ex83 step 3) `iavrr = iadrr = 0`
  and the code reads `nbond(0)`: index 0 of the Python arrays is 0, which is what the
  Fortran reads (the preceding COMMON element, never set). A DIH group with atoms 0 0 is
  created, as in the Fortran.
- `random_rotatem`: `sphinew` is not set when neither `iadrr` nor `iavrr` is found; the
  Fortran prints stack garbage (e.g. `0.414924E-41`), the Python prints 0 (stdout only).
  `cphiold`/`sphiold` likewise (only printed when `iavrr > 0`, in which case they are set
  unless `iadrr = 0`). `rdpvector`/`rvpvector` keep the value of the last candidate atom
  examined, which is not necessarily the one accepted; reproduced.
- `search_unsaturated`: `imv` is printed before being set when the loop does not run; 0.
- `addato`: the existence test of the molecule template opens the blank-padded
  `character*256` name followed by `.ato`, which never exists, so the template always
  becomes the name of the file read (reproduced with `pad(moltemplate, 256) + '.ato'`).
- `addato`: the copy of the rotational-group atom lists indexes `nrot`, `rotf` and
  `rotgrp` with `ig` instead of `irgref`; `ndihedralangs`, `dihedralangs`, `labrotdihs`,
  `labrots` are reallocated with `nmix` instead of `nmixmax`; when `imix` exceeds
  `nmixmax` only the 1-D arrays are grown. All reproduced (an out-of-range index would
  raise in Python where the Fortran overwrites memory; not reached by the tests).
- `addato`: `ext`, `ilenext`, `nmix` are blank/0 if the Fortran would use them
  uninitialised (nmix <= 0, or an unreadable first answer).
- `addato`/`dockato`: the loops that re-ask on a read error (`read(5,*,iostat=ierr) nmix`)
  loop forever at end of input, as in the Fortran.
