# Translation guide (read this before translating any Fortran)

This is the working rulebook for translating `fortran_src/` into `src/epsr26/`. It expands
PLAN.md section 2 with the conventions the code actually uses. The aim is that any line of
Python can be checked against the Fortran line it came from, and that the output files are
**byte-identical** to the Fortran's.

Reference material, keep it open while translating:

- the Fortran: `fortran_src/<file>`;
- the Rust port, which has already solved every mixed-precision cast and quirk:
  `~/EPSRpy/rust/epsr-core/src/` (map: `docs/rust_port/FORTRAN_MAP.md`; tools:
  `docs/rust_port/TOOLS.md`). The Rust is a *guide*; the Python follows the **Fortran's**
  structure (one function per routine, same names, same order of operations);
- `docs/SIGNATURES.md`: every routine's arguments and what the Python returns (the
  contract between files, see section 3);
- `docs/FORTRAN_BUGS.md`: the five bugs fixed on purpose (section 1); everything else is
  reproduced.

## 1. Files and modules

| Fortran | Python |
|---|---|
| a file with a `program` | `src/epsr26/programs/<file>.py`, with `main()` translating the program body |
| a file of shared routines | `src/epsr26/library/<file>.py` |
| `include 'x.inc'` | `from ..common import x` (generated by `tools/gen/gen_common.py`; never edit) |
| Fortran `module m` data | `src/epsr26/common/<m>.py` (hand-written; see 5.2) |
| Fortran `module m` routines | in the library module of the file that contains the module |

File names: `X-rayf0.inc` -> `common/x_rayf0.py`; `ato_manipulation_rev4.f` ->
`library/ato_manipulation_rev4.py`. Keep the Fortran's order of routines in the file.

Every translated routine:

```python
@routine
def molfit(fadds, faddbs, nisum, intra, rotfreq, ireset):
    """molfit.f:molfit -- one Monte Carlo cycle.

    <one or two lines from the Fortran header comment>
    Returns (fadds, faddbs, nisum).
    """
```

- `@routine` (from `..trace`) on every routine, including small ones. It costs nothing
  unless tracing is on.
- The docstring starts with `file:routine`.
- Keep the Fortran comments (as `#` comments), including commented-out code only where it
  helps understanding. Keep statement labels that are jump targets as comments
  (`# 3000 continue`).

Imports, always **modules, never names** (tracing and `common.reset()` replace module
attributes, so `from x import f` would bypass them):

```python
from ..fortran import *                      # f32, r4, fmt, lw, Ch, units, fstr, idiv, ...
from ..fortran import runtime                # getarg, system, ...
from ..common import molecom, clustercom, epsr_dimension
from ..common import molecom_mod             # Fortran module data
from . import auxiliary_routines, parse      # other library files
from ..trace import routine
```

and call `parse.parse(...)`, `auxiliary_routines.ran1()`, `molecom.xa[i]`. Within the same
file call the routine by its bare name. To break an import cycle import inside the function.

## 2. Types and arithmetic (the part that decides byte identity)

| Fortran | Python |
|---|---|
| `real`, `real*4` | `numpy.float32` scalar (`f32`) |
| `real*8`, `double precision` | Python `float` |
| `integer` | Python `int` (elements of integer arrays are `numpy.int32`) |
| `integer*8` | Python `int` (`I8(v)` when written list-directed) |
| `logical` | `bool` |
| `character*n` | `str` without trailing blanks (section 6) |

**Implicit typing.** Most routines have no `implicit none`: an undeclared variable whose
name starts with `i`-`n` is an `integer`, anything else is a `real`. A `real` local must
start life as `f32(0.0)` (or its first assignment must produce a float32), never `0.0`.

Rules (the reason is in `src/epsr26/fortran/fmath.py`):

1. **Integer -> real conversions are explicit.** `x*i` in Fortran is `x * f32(i)`;
   `real(i)`/`float(i)` is `f32(i)`. `numpy.int32 * numpy.float32` gives float64 in NumPy,
   so an element of an integer array mixed into a real expression silently changes the
   precision. Write `f32(...)` every time an integer meets a real.
2. **real -> integer** assignment `i = x` is `i = ifix(x)` (truncation); `nint(x)` is `nint(x)`.
3. **Single-precision literals.** `x + 0.5` with `x` float32 is fine (NumPy turns the
   Python literal into float32, as Fortran's `0.5` is real*4). A literal that does not meet
   a float32 operand directly must be wrapped: `y = f32(0.5)`, `a = r4(2.0) * f32(n)`,
   `max(x, f32(0.0))`, `min(r, r4(1.0))`. Constant expressions are folded in single
   precision by gfortran: `1.0/3.0` -> `r4(1.0) / r4(3.0)`. `4.0*atan(1.0)` -> `PI4ATAN`.
4. **real*8.** Python floats. A real meets a real*8: convert explicitly, `d + float(x)`.
   A *single-precision literal* in a double expression is converted from single:
   `d * 0.1` -> `d * float(r4(0.1))` (exactly representable literals such as `0.5`, `2.0`
   need no care). `1.0d0` -> `1.0`. `x = d` (real <- real*8) -> `x = f32(d)`.
5. **Order of operations** is left to right, exactly as written: `a + b + c` is
   `(a + b) + c`. Never reassociate, never factor, never use `sum()`, `np.sum`, `np.dot`,
   `math.fsum` or vectorised NumPy expressions on data. Loops stay loops, in the Fortran
   order. (Copying arrays and filling with a constant are fine: `a[:] = 0`, `b[:, j] = a[:, k]`.)
6. **Storing into a float32 array** rounds whatever you give it. If the expression is
   float64 by mistake, NumPy rounds once at the end and the bits differ from Fortran's
   step-by-step float32. Make sure the expression is already float32.
7. **Powers:** `x**2` -> `x*x`, `x**3` -> `x*x*x`, `x**4` -> `pow4(x)`, `x**n` (integer
   variable) -> `powi(x, n)`, real*8 `d**n` -> `powi_d(d, n)`, `x**y` real -> `powf(x, y)`,
   `d**y` double -> `math.pow(d, y)`, `x**0.5` -> `powf(x, f32(0.5))` (gfortran calls powf).
8. **Intrinsics:**

| Fortran (real*4) | Python | Fortran (real*8) | Python |
|---|---|---|---|
| `sqrt` | `sqrtf` | `sqrt`/`dsqrt` | `dsqrt` (or `math.sqrt` if arg >= 0) |
| `exp log log10` | `expf logf log10f` | `exp log` | `math.exp math.log` |
| `sin cos tan` | `sinf cosf tanf` | | `math.sin ...` |
| `asin acos atan atan2` | `asinf acosf atanf atan2f` | | `math.acos ...` |
| `sinh cosh tanh` | `sinhf coshf tanhf` | | |
| `abs` | `abs` | `abs` | `abs` |
| `mod(a,b)` real | `amod(a, b)` | `mod(i,j)` integer | `imod(i, j)` |
| `i/j` integer | `idiv(i, j)` | `sign(a,b)` | `sign` / `isign` / `dsign` |
| `nint int aint anint` | `nint ifix aint anint` | `max min` | `max min` (same types!) |
| `sind cosd` gfortran intrinsic | `sind_intrinsic cosd_intrinsic` | EPSR's own `sind`/`cosd` | `auxiliary_routines.sind` |

   EPSR defines its own `cosd`, `sind`, `acosd`, ... in `auxiliary_routines.f`. A unit that
   declares them `external` (or calls them where gfortran resolves to the user function)
   uses EPSR's; otherwise gfortran's intrinsic. The Rust code says which; follow it.
9. **Integers** wrap at 32 bits in Fortran; Python ints do not. Use `wrap32()` only where
   wrap-around actually happens (hashing, `ran1` is written to avoid it). Integer `/` is
   `idiv` and `mod` is `imod` whenever an operand can be negative; for non-negative
   operands `//` and `%` are equivalent and acceptable.
10. **Comparisons of reals** with literals: `x > 0.0` is fine.
11. **OpenMP**: the reference runs with `OMP_NUM_THREADS=1`, so a parallel loop is the
    serial loop in order. Keep `!$omp` lines as comments. `omp_get_thread_num()` -> 0,
    `omp_get_num_threads()`/`omp_get_max_threads()` -> 1.

## 3. Arguments and the calling convention

- The Python function takes **the same arguments, in the same order**, as the Fortran.
- Arrays are NumPy arrays (section 4) and are modified in place.
- The function **returns every scalar dummy it may assign, in argument order** (one value,
  or a tuple). A `function` returns its result first, then those scalars. The list for
  every routine is in `docs/SIGNATURES.md`; it is the contract, so callers can be written
  before the callee exists:

  ```python
  # call molfit(fadds,faddbs,nisum,intra,rotfreq,ireset)    returns: fadds, faddbs, nisum
  fadds, faddbs, nisum = molfit.molfit(fadds, faddbs, nisum, intra, rotfreq, ireset)
  ```

  If you find that `SIGNATURES.md` is wrong for a routine you translate (it misses an
  assigned scalar, or lists one that is never assigned), **follow SIGNATURES.md anyway** and
  add a line to `docs/SIGNATURE_EXCEPTIONS.md` (`routine: what is wrong`). Consistency
  between files matters more than the extra value; we fix both sides together.
- A scalar actual argument that is an element of an array (`call foo(a(i))` where foo
  assigns its dummy) -> `a[i] = foo.foo(a[i])`.
- **Sequence association**: passing `a(1,j)` to a routine whose dummy is a 1-D array ->
  pass the column view `a[:, j]` (index 0 of the view is then the unused `a[0, j]`, and
  `view[k]` is `a(k,j)`). Passing `a(k)` with k > 1 to a 1-D dummy -> pass `a[k - 1:]`.
  If a 2-D array is passed to a dummy of different shape, reshape a view with
  `order='F'` and say so in a comment.
- `character(len=*)` dummies: pass the Python string; if the callee needs `len(dummy)`,
  add a keyword argument with the declared length (see `library/parse.py:concatenate`).
- `optional` + `present(x)` -> keyword argument defaulting to `None`.
- A COMMON variable passed as an actual argument and assigned by the callee: assign the
  returned value back to the module attribute (`molecom.natom = foo.foo(molecom.natom)`).

## 4. Arrays

```python
a = real_array(n, m)        # real a(n,m)       -> a[i, j] is a(i,j); index 0 unused
b = int_array(mpz)          # integer b(mpz)
c = dble_array((0, n))      # real*8 c(0:n)     -> lower bound 0 is index 0
s = char_array(mcomp)       # character*3 s(mcomp) -> object array of '' strings
```

- Column-major (`order='F'`), one extra element per dimension.
- Local arrays are created at the start of the routine with these helpers (zeroed).
  Fortran's local arrays are uninitialised; if the code reads an element before writing
  it, see section 8.
- `allocatable` arrays start as `None`; `allocate(a(n))` -> `a = real_array(n)`;
  `allocated(a)` -> `a is not None`; `deallocate(a)` -> `a = None`. Lower bounds other
  than 1 or 0 need an explicit offset (say so in a comment).
- `size(a)` -> `a.shape[0] - 1` (or per dimension).
- Implied-do in I/O lists becomes a list comprehension inside the call:
  `fmt('(10f8.3)', *[a[i] for i in range(1, n + 1)])` (this is not arithmetic, it is fine).

## 5. Global state

### 5.1 COMMON blocks / include files

`common/<inc>.py` modules are generated. Access every variable through the module:
`molecom.xa[i]`, `clustercom.nmol = nmol + 1`. Parameters are module constants
(`epsr_dimension.mpairs`). Each module's docstring lists any variables that the include
declares outside a COMMON block (`LOCALS`): those are locals of every routine that includes
the file and must be created in the routine.

A `common /blk/` written directly inside a routine (e.g. `common/sumvalues/` in
`epsr_standalone_rev3.f`) becomes a small hand-written module `common/<blk>.py` with a
`reset()` function, registered with `common.register(module)` at import.

### 5.2 Fortran module data

`module molecom_mod` -> `src/epsr26/common/molecom_mod.py`: module variables as globals,
`reset()` recreating them (allocatables `None`, initialised variables to their initial
value), and at the end:

```python
from . import register
import sys
register(sys.modules[__name__])
reset()
```

The routines of the module (after `contains`) go in the library file. The data module name
is the Fortran module name (`ergpairstore`, `ergpairreference`, `cellneighbourlist`,
`timer`, `diffuse_mod`, `threebody_mod`, ...), so other files can use it before it exists.

### 5.3 SAVEd locals

A local with `save`, a DATA statement, or an initialisation in its declaration
(`integer :: icall = 0` implies SAVE) keeps its value between calls *within one program*:

```python
_save = common.SaveBlock("molfit", icall=0)     # module level, next to the routine
...
_save.icall = _save.icall + 1
```

`common.reset()` restores the initial values before each program. Locals without SAVE
are re-created on every call (gfortran with `-fopenmp` puts them on the stack).

## 6. Characters

Character variables are Python strings **without trailing blanks**, so `==` behaves
like Fortran's `.eq.` (which ignores trailing blanks).

| Fortran | Python |
|---|---|
| `s = expr` (`character*n s`) | `s = fstr(expr, n)` (truncate to n, drop trailing blanks) |
| `s(i:j)` | `substr(s, i, j)` (blank-padded to j-i+1) |
| `s(i:i) .eq. ' '` | `substr(s, i, i) == ' '` |
| `s(i:j) = t` | `s = setsub(s, i, j, t, n)` |
| `index(s, t)` | `findex(s, t)`; when t contains a blank, `findex_padded(s, t, n)` |
| `len_trim(s)` | `len(s)` |
| `len(s)` | `n` (the declared length) |
| `s // t` | `s + t` when s is a trimmed substring; `pad(s, n) + t` if s's padding matters |
| `write(u,'(a)') s` | `fmt('(a)', Ch(s, n))` — the padding reaches the output |
| `write(u,*) s` | `lw(Ch(s, n))` |
| `ichar(c)`, `char(i)` | `ord(c)`, `chr(i)` |
| `read(u,'(a)') s` | `s = fstr(units.read_line(u), n)` |

`Ch(s, n)` is only needed where the full declared length is written; `fname(1:nchar)` is
just `substr(fname, 1, nchar)` (a plain `str`).

## 7. Control flow

- `do 10 i = 1, n` -> `for i in range(1, n + 1):`. Steps: `do i = n, 1, -1` ->
  `range(n, 0, -1)`. **After the loop** Fortran's `i` is `n + 1` (or the start value if
  the loop did not run); Python's is `n` (or unset). If the variable is used after the
  loop, set it explicitly or use a `while` loop.
- The loop bounds are evaluated once, before the loop (Python's `range` does the same).
- `do while (...)` -> `while ...:`. `exit` -> `break`, `cycle` -> `continue`.
- `goto` -> restructure into loops/flags; keep the label as a comment. Avoid clever
  rewrites; prefer `while True:` + `break` that mirrors the jumps.
- `stop` / `stop 'text'` -> `raise FortranStop(0, 'text')`. `call exit(n)` ->
  `raise FortranStop(n)`.
- `return` in the middle of a routine -> `return <the returned scalars>`.

## 8. Uninitialised variables, quirks and known bugs

Reproduce the Fortran, quirks included. Where the Fortran reads a variable that was never
set (stack garbage), the Rust port documents what value reproduces the reference (usually
0, or the value from a previous call); do the same and mark it:

```python
# NB: nfound is not initialised in the Fortran; 0 reproduces the reference (Rust nwts.rs:84)
```

The five bugs in `docs/FORTRAN_BUGS.md` section 1 are fixed the same way the Rust fixed
them; mark each site with `# FIX (FORTRAN_BUGS.md 1.x): ...`. Do not fix anything else.

## 9. Input and output

`from ..fortran import units` and `fmt`, `lw`:

| Fortran | Python |
|---|---|
| `open(10, file=f, status='old', err=99)` | `try: units.open(10, f, status='old')` / `except FortranIOError:` |
| `close(10)` | `units.close(10)` |
| `read(10, '(a)', end=99) line` | `line = fstr(units.read_line(10), n)` in `try`/`except FortranEOF` |
| `read(10, *) n, x` | `r = units.list_read(10); n = r.int(n); x = r.real(x)` |
| `read(10, *)` (skip) | `units.skip_record(10)` |
| `read(line, *) x` (internal) | `x = read_internal(line).real(x)` |
| `read(10, '(i7,3g14.7)') i, a, b, c` | `i, a, b, c = units.read_fmt(10, '(i7,3g14.7)')` |
| `write(10, '(a,i5)') s, n` | `units.write(10, fmt('(a,i5)', s, n))` |
| `write(10, 100) ...` / `100 format(...)` | `_F100 = '(...)'` at module level, `fmt(_F100, ...)` |
| `write(6, *) 'x', y` / `print *, ...` | `units.write(6, lw('x', y))` |
| `write(6, '(a)', advance='no') p` | `units.write(6, p, advance=False)` |
| `write(text, '(i5)') n` (internal) | `text = fstr(fmt('(i5)', n), len_of_text)` |
| `backspace 10`, `rewind 10` | `units.backspace(10)`, `units.rewind(10)` |
| `inquire(file=f, exist=ex)` | `ex = units.inquire_exists(f)` |
| `iostat=ios` | `ios = 0` + `try ... except FortranEOF: ios = -1 except FortranIOError as e: ios = e.iostat` |
| `read(5, *)`, `read(*, ...)` | unit 5 (standard input) |
| `call getarg(i, s)` | `s = fstr(runtime.getarg(i), n)` |
| `call system(cmd)` | `runtime.system(cmd)` |

The value types decide the conversion (`fformat.py`): float32 is written as real*4
(list-directed: 9 significant digits), Python float as real*8 (17 digits). Make sure a
real*4 variable really is a float32 when written.

Files are held in memory and written on `close` (or at the end of the program), so
reading a file to its end and then writing to it appends, as in Fortran.

## 10. Checking your translation

1. `python -c "import epsr26.library.<module>"` must work, and
   `ruff check src/epsr26/<path>` must be clean (or only style warnings).
2. Read your translation against the Fortran once more, line by line, looking for: missing
   `f32()` on integer->real, float literals that are not float32, real*8 mixing, loop
   variables used after the loop, `/` on integers, character lengths.
3. Where a routine can be exercised alone (I/O routines, parsing), compare with the Fortran
   on a real file from `EPSR-test/`.
4. The real test is the end-to-end comparison: `tools/run_ex_test_py.sh` (see
   `docs/PROGRESS.md`).

## 11. Conventions settled during the first integration (wave 1, engine)

These came out of merging the engine and are now the rule:

- **Reallocation returns the array.** `arr = reallocation_routines.reallocate1d_i(arr, n)`;
  a routine that reallocates an allocatable dummy returns it (e.g. `get_rotgrp` returns
  `(labrott, nrott)`). See `docs/SIGNATURE_EXCEPTIONS.md` for every such case.
- **Same-name modules.** `common/<m>.py` (module data) and `library/<m>.py` (routines) can
  share a name (`molecom_mod`, `cellneighbourlist`, `ergpairreference`, `threebody_mod`,
  `containerforces_mod`, `lngamma_mod`, `coordconstraint_mod`). Import the library one
  with a suffix: `from ..library import cellneighbourlist as cellneighbourlist_lib`.
- **Import cycles:** import the other library module inside the function that needs it.
- **Name the compat imports** (`from ..fortran import f32, fmt, ...`) rather than `*`, so
  `ruff check --select F` reports genuinely undefined names.
- **iostat:** `except (FortranEOF, FortranIOError) as e: ios = iostat_of(e)`.
- gfortran's `atan2d` is `atan2d_intrinsic`; FORMAT now accepts `0x`, `0(...)` and `*(...)`.
- `$` in a FORMAT is not supported: drop it and write with `advance=False` (keep the
  original format as a comment). A trailing `1x` before a non-advancing end is written by
  gfortran: add the blank yourself.
- Real arguments passed to translated routines must be float32 (`f32(...)`), never plain
  Python floats.
- Programs: `def main():` in `programs/<file>.py`; `get_command_from_args()` reads the
  arguments installed by `programs.run_program` (folder, command, rest).

## 12. Testing a program end to end

`tools/run_ex_py.py CASE_DIR` runs every step of a test case with the Fortran
(`fortran_build/`) and the Python and compares all files after each step (resume mode:
each Python step starts from the Fortran's folder before that step). Example:

    . .venv/bin/activate
    python tools/run_ex_py.py test_problems/200DMSO400Water/EPSR-test-ex28 --work work/me/ex28

Cases using a program: `grep -l '^nwts' test_problems/200DMSO400Water/*/commands.txt`.
The first `epsr` pass of EPSR-test-ex1 is byte-identical this way (every output file).
